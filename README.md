# مترجم هوشمند EPUB

**🌐 زبان‌ها:** فارسی · [English](https://github.com/Retro-Zero/epub-ai-translator/blob/main/README.en.md)

یک وب‌اپ **self-hosted** برای ترجمه‌ی کتاب‌های EPUB انگلیسی به فارسی، با یک **human-in-the-loop** واقعی در مراحل مهم.

کتاب را آپلود می‌کنید، ساختارش را قبل از شروع می‌بینید، Glossary اسم‌ها و اصطلاحات را بررسی و تأیید می‌کنید، ترجمه را فصل‌به‌فصل با progress زنده دنبال می‌کنید، خروجی را در مرحله‌ی QA بررسی می‌کنید و در نهایت یک EPUB فارسی RTL تحویل می‌گیرید.

ساختار اصلی کتاب، تصاویر، CSS و فهرست آن حفظ می‌شوند.

> **کاملاً local و تک‌کاربره:** بدون account، بدون cloud و بدون database. **BYOK:** API key خودتان را استفاده می‌کنید و فقط هزینه‌ی tokenهای مصرف‌شده را به provider می‌پردازید.

**تازه‌کار هستید و نمی‌دونید از کجا شروع کنید؟** یک راهنمای قدم‌به‌قدم مخصوص کسانی که تا حالا کدنویسی نکرده‌اند آماده کرده‌ایم: **[راهنمای کامل نصب برای مبتدی‌ها →](TUTORIAL_FA.md)**

## ✨ قابلیت‌ها

### ۱. آپلود و بررسی EPUB
فایل `.epub` را آپلود کنید و قبل از اینکه چیزی ساخته یا ترجمه شود، اطلاعات اولیه‌ی کتاب را ببینید: عنوان، حجم فایل، تعداد فصل‌ها، تعداد content nodeها.

### ۲. اتصال به Provider دلخواه
می‌توانید از این providerها استفاده کنید: DeepSeek، OpenAI، Gemini، یا هر endpoint سازگار با OpenAI (مثل Ollama یا Groq).

API key به‌صورت local روی دستگاه شما ذخیره می‌شود و به هیچ سرویس دیگری ارسال نمی‌شود. قبل از شروع ترجمه هم می‌توانید با یک درخواست ارزان، اتصال و API key را تست کنید.

### ۳. Glossary با تأیید کاربر
اسم شخصیت‌ها و اصطلاحات تکرارشونده از اولین فصل محتوایی استخراج می‌شوند. AI برای هر مورد یک ترجمه‌ی فارسی پیشنهاد می‌دهد و شما می‌توانید ترجمه را تغییر دهید، یادداشت اضافه کنید یا مورد را تأیید کنید. بعد از تأیید، این موارد به‌عنوان ترجمه‌های **ثابت و اجباری** در تمام ترجمه‌های کتاب استفاده می‌شوند.

### ۴. ترجمه‌ی فصل‌به‌فصل
ترجمه‌ی کل کتاب در پس‌زمینه انجام می‌شود و progress هر فصل به‌صورت زنده نمایش داده می‌شود. اگر یک فصل fail شود، بقیه‌ی کتاب متوقف نمی‌شود، مشکل همان فصل باقی می‌ماند و امکان retry همان فصل وجود دارد. Batchها هم با محدودیت concurrency و rate limit اجرا می‌شوند.

### ۵. بازبینی QA
یک مرحله‌ی اختیاری برای بررسی کیفیت و consistency ترجمه وجود دارد. نمونه‌ای از ترجمه‌ها از نظر استفاده از Glossary، انتقال معنا، روان بودن فارسی و لحن بررسی می‌شوند. متن اصلی و ترجمه کنار هم نمایش داده می‌شوند و برای مشکلات پیدا‌شده، پیشنهاد اصلاح قابل ویرایش ارائه می‌شود. در نهایت می‌توانید هر پیشنهاد را **Accept** یا **Keep** کنید.

### ۶. نرمال‌سازی نیم‌فاصله‌ی فارسی
مدل‌های زبانی گاهی نیم‌فاصله (ZWNJ) را در واژه‌های مرکب فارسی جا می‌اندازند (مثلاً «می‌شود» را به‌صورت «میشود» برمی‌گردانند). یک لایه‌ی نرمال‌سازی، دقیقاً در نقطه‌ی خروجی مترجم و همچنین روی اصلاحات QA، این موارد را اصلاح می‌کند:

- یک دیکشنری قابل‌بازبینی با حدود ۱۵۰ واژه‌ی دقیق
- یک قاعده‌ی مولّد برای «می + فعل» که از ۳۴ جفت فعل ساخته شده، برای پوشش کامل صرف‌ها
- محافظت با word-boundary، تا مثلاً «کتاب‌ها» هرگز داخل «کتاب‌هایم» فعال نشود
- «همه‌ی» با ی میانجی عمداً دست‌نخورده باقی می‌ماند
- متن انگلیسی/ASCII و متنی که از قبل درست است، بدون تغییر عبور می‌کند
- این پردازش idempotent است و هیچ هزینه‌ی API اضافه‌ای ندارد

### ۷. Finalize
در مرحله‌ی نهایی: اصلاحات تأییدشده اعمال می‌شوند، `lang="fa"` و `dir="rtl"` تنظیم می‌شوند، فونت **Vazirmatn** داخل EPUB embed می‌شود (همراه با لایسنس SIL OFL 1.1)، عنوان و TOC ترجمه می‌شوند و EPUB نهایی آماده‌ی دانلود می‌شود.

ساختار اصلی کتاب، تصاویر، CSS و TOC حفظ می‌شوند.

## 💰 هزینه‌ی ترجمه

هزینه‌ی مصرف‌شده در هر job داخل برنامه نمایش داده می‌شود. همچنین می‌توانید tokenهای مصرف‌شده و هزینه‌ی تخمینی را بر اساس قیمت provider ببینید، هزینه‌ی احتمالی باقی‌مانده را حین ترجمه دنبال کنید و قیمت input/output هر provider را در Settings تغییر دهید.

برای مرجع: ترجمه‌ی کامل یک رمان معمولی (چیزی شبیه «بیمار خاموش») حدود ۶۱۵ هزار توکن مصرف کرد و کمتر از **۴۰ سِنت** هزینه داشت — با provider ارزان مثل DeepSeek.

---

## 🛡️ Round-trip Fidelity Gate

قبل از اینکه ترجمه به محتوای کتاب دست بزند، EPUB یک **round-trip verification** کامل را پشت سر می‌گذارد. EPUB بازسازی‌شده باید از نظر ساختار و محتوای دست‌نخورده، با فایل اصلی مطابقت داشته باشد. این Gate بررسی می‌کند که: ترتیب ورودی‌های ZIP یکسان باشد، فایل‌های دست‌نخورده مثل CSS/تصاویر/فونت/OPF/NCX/TOC دقیقاً یکسان باشند، `mimetype` همچنان `stored` باشد، تمام فصل‌های بازسازی‌شده XML معتبر داشته باشند، و متن ساده‌ی هر فصل قبل و بعد از rebuild یکسان باشد.

برای هر job یک `report.json` ساخته می‌شود که نتیجه‌ی هر ۵ بررسی را ثبت می‌کند. اگر هر کدام fail شود، job متوقف می‌شود.

## 🧠 مقاومت در برابر رفتارهای عجیب مدل

مدل‌های زبانی همیشه دقیقاً همان چیزی را که انتظار داریم برنمی‌گردانند. Translator برای بعضی از خطاهای رایج recovery دارد؛ مثلاً وقتی مدل برای یک node پاسخ خالی برمی‌گرداند، بعضی آیتم‌های یک batch را جا می‌اندازد، یا پاسخ ناقص برمی‌گرداند. در این شرایط، nodeهای مشکل‌دار متن اصلی خودشان را حفظ می‌کنند و ترجمه‌ی فصل ادامه پیدا می‌کند، به‌جای اینکه کل کتاب fail شود.

## 🧰 تکنولوژی

**Backend:** Python 3.11 · FastAPI · ebooklib · BeautifulSoup · lxml · ZIP manipulation با standard library

**Frontend:** React 18 · Vite · Functional Components + Hooks · CSS مینیمال · Polling برای وضعیت job (بدون WebSocket، بدون UI framework)

**Storage:** تمام داده‌ها به‌صورت local در `data/jobs/<job_id>/` ذخیره می‌شوند. هیچ databaseای استفاده نمی‌شود.

**Translation:** از طریق SDK کتابخانه‌ی `openai` و APIهای سازگار با OpenAI انجام می‌شود. Preset فعلی برای `deepseek-v4-flash` تنظیم شده و شامل batching، rate-limit awareness، concurrency محدود و recovery پاسخ‌های خالی است.

## 🚀 نصب و اجرا

> اگر با ترمینال و ابزارهای برنامه‌نویسی راحت نیستید، همان بهتر که از **[راهنمای مبتدی‌ها](TUTORIAL_FA.md)** شروع کنید. بخش زیر برای کسانی است که از قبل با Python/Node کار کرده‌اند.

### پیش‌نیازها
- Python 3.10+ (پیشنهاد: 3.11)
- Node.js 18+

### ۱. نصب Backend
```bash
uv venv --python 3.11
uv pip install --python .venv/bin/python -r backend/requirements.txt
cp backend/.env.example backend/.env
```
فایل `.env` اختیاری است و می‌توانید از آن برای fallback API key استفاده کنید.

### ۲. Build کردن Frontend
```bash
cd frontend
npm install
npm run build
cd ..
```
خروجی build داخل `backend/static` قرار می‌گیرد.

### ۳. اجرای برنامه
```bash
cd backend
../.venv/bin/uvicorn app.main:app --port 8000
```
بعد مرورگر را باز کنید: http://127.0.0.1:8000

از Settings می‌توانید Provider، مدل و API key را تنظیم کنید. قبل از شروع ترجمه، دکمه‌ی **Test connection** یک درخواست ارزان برای بررسی اتصال اجرا می‌کند.

### Development mode
```bash
cd frontend
npm run dev
```

| گزینه | توضیح |
|---|---|

| **Model** | مدل پیشنهادی برای هر provider یا مقدار دلخواه برای Custom |

API key روی سیستم خودتان باقی می‌ماند، در UI به‌صورت mask نمایش داده می‌شود، به‌صورت کامل از API برگردانده نمی‌شود، فایل تنظیمات با `gitignore` محافظت می‌شود و با `chmod 600` محدود می‌شود.

| Method | Endpoint | توضیح |
|---|---|---|
| `POST` | `/preview` | Parse کردن EPUB بدون ساخت job |

| `POST` | `/translate/{id}/all` | ترجمه‌ی کل کتاب |
| `POST` | `/qa/{id}` | اجرای QA |
| `GET` | `/qa/{id}` | دریافت نتایج QA |
| `PUT` | `/qa/{id}/fixes` | اعمال تصمیم‌های QA |

## 🧪 تست رایگان (Mock mode)

توی Settings کلید «Mock mode» رو روشن کنید — کل pipeline (glossary، ترجمه‌ی کل کتاب، QA، finalize و دانلود) روی یه fake داخلی اجرا می‌شه: صفر درخواست API، صفر هزینه، بدون نیاز به کلید. همه‌ی خروجی‌ها واضح علامت‌گذاری می‌شن (**【آزمایشی】**) که هیچ‌وقت با ترجمه‌ی واقعی اشتباه گرفته نشن. توی صفحه‌ی آپلود هم دکمه‌ی «کتاب نمونه» هست برای تست یک‌کلیکی.

## 🧪 تست

```bash
.venv/bin/python -m pytest
```

در حال حاضر **۹۰ تست** وجود دارد که این بخش‌ها را پوشش می‌دهند: Round-trip verification، Translator (شامل بازیابی از پاسخ خالی/ناقص)، Glossary، QA (شامل background task و resilience)، Finalize، Settings، Preview، و نرمال‌سازی نیم‌فاصله.

برای استفاده از EPUBهای واقعی به‌عنوان fixture:
```
test-epubs/
```
این پوشه `gitignored` است.

همچنین می‌توانید rebuild را از CLI روی یک EPUB اجرا کنید:
```bash
python backend/demo.py book.epub
```
